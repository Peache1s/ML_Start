# Used Car Price Prediction

**Проект дополняется, README будет переформулирован в ближайшее время и проведен рефакторинг кода*

## Датасет

Для решения задачи предсказания рыночной цены подержанных автомобилей был выбран датасет **"Used Car Price Prediction Dataset"** с платформы Kaggle.

**Почему выбран этот датасет:**
*   Данные собраны с реального автомобильного маркетплейса [cars.com](https://www.cars.com) и содержат 4009 записей о продаже.
*   Включает широкий набор признаков, влияющих на цену: марка, модель, год выпуска, пробег, тип топлива, характеристики двигателя, тип коробки передач, цвета, история ДТП и юридическая чистота (Clean Title).
*   Набор данных хорошо подходит для решения задачи регрессии и позволяет применить различные методы Feature Engineering и машинного обучения.

**Ссылка на данные:** [Used Car Price Prediction Dataset on Kaggle](https://www.kaggle.com/datasets/taeefnajib/used-car-price-prediction-dataset)

## Список гипотез (до начала работы)

Перед началом анализа и моделирования были выдвинуты следующие гипотезы:

1.  **Гипотеза 1:** Использование новых признаков, полученных из колонок `engine` и `transmission` (объем, мощность, наличие турбо, тип КПП), позволит существенно улучшить качество линейной регрессии по сравнению с использованием изначальных текстовых колонок.
2.  **Гипотеза 2:** Добавление бинарного признака пропуска `trans_speed_number_miss` может улучшить качество линейной регрессии, так как пропуски в этой колонке не случайны.
3.  **Гипотеза 3:** Добавление бинарного признака пропуска `engine_power_miss` может сильно улучшить качество линейной регрессии и стать одним из самых важных признаков, учитывая сильную разницу в цене между машинами с пропуском и без него.
4.  **Гипотеза 4 (Lasso):** Использование Lasso-регрессии с подбором гиперпараметров позволит улучшить качество модели за счет автоматического отбора наиболее значимых признаков.
5.  **Гипотеза 5 (RFE):** Использование Recursive Feature Elimination (RFE) для отбора признаков перед обучением линейной регрессии улучшит качество модели и ее интерпретируемость.
6.  **Гипотеза 6 (Дерево решений):** Использование нелинейной модели, такой как дерево решений, позволит улучшить качество предсказаний за счет учета сложных зависимостей, которые не может уловить линейная модель.

## Краткие результаты

В ходе работы были проверены все выдвинутые гипотезы. Основные результаты представлены в таблице ниже.

**Сравнение качества моделей (RMSLE, mean ± std по 5 фолдам CV)**

| Модель | RMSLE (CV) |
| :--- | :--- |
| **Baseline (линейная регрессия на логарифм цены)** | 0.4753 ± 0.0166 |
| **Baseline + Parsed features (объем, мощность, турбо, тип КПП)** | 0.3771 ± 0.0136 |
| **Baseline + Parsed features + Raw `engine` и `transmission`** | 0.3690 ± 0.0140 |
| **Baseline + `trans_speed_number_miss`** | 0.4741 ± 0.0178 |
| **Baseline + `engine_power_miss`** | 0.4746 ± 0.0166 |
| **Lasso (с подбором `alpha`)** | 0.417 |
| **Linear Regression + RFE** | 0.3690 ± 0.0140 |
| **Decision Tree (с подбором гиперпараметров через Optuna)** | 0.4093 ± 0.0085 |

### Что подтвердилось

1.  **Гипотеза 1 подтверждена.** Использование распаршенных признаков из `engine` и `transmission` дало значительное улучшение: RMSLE снизился с 0.475 до 0.377.
2.  **Добавление сырых текстовых признаков.** Добавление исходных колонок `engine` и `transmission` к распаршенным признакам дало дополнительное небольшое улучшение (RMSLE: 0.369), что подтверждает наличие в тексте информации, не учтенной при парсинге.
3.  **RFE.** Использование Recursive Feature Elimination позволило достичь качества, сравнимого с лучшей линейной моделью (RMSLE: 0.369), при этом сократив количество признаков и упростив модель.

### Что не подтвердилось

1.  **Гипотеза 2 не подтвердилась.** Добавление бинарного признака `trans_speed_number_miss` не дало улучшения (RMSLE: 0.474). Разница с базовой моделью находится в пределах статистической погрешности.
2.  **Гипотеза 3 не подтвердилась.** Несмотря на сильный сигнал в данных (разница в средней цене ~$28k), добавление `engine_power_miss` не улучшило качество линейной регрессии (RMSLE: 0.474). Вероятно, информация о пропусках уже учтена через другие признаки.
3.  **Гипотеза 4 (Lasso) не подтвердилась.** Lasso-регрессия показала худший результат (RMSLE ~0.417), что говорит о том, что регуляризация в данном случае не нужна, а обнуление коэффициентов приводит к потере полезной информации.
4.  **Гипотеза 6 (Дерево решений) не подтвердилась.** Дерево решений с подбором гиперпараметров не превзошло линейную модель (RMSLE: 0.409). Это указывает на то, что для данного датасета линейные зависимости все еще играют ключевую роль.

## Выводы

Наилучший результат (RMSLE 0.369) был достигнут линейной регрессией с использованием распаршенных признаков из `engine` и `transmission`, а также исходных текстовых колонок. Дальнейшее усложнение модели (дерево решений, Lasso) не привело к улучшению, что говорит о том, что для данного датасета линейные зависимости являются основными.
